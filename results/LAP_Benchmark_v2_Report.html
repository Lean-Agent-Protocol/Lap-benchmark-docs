0 Abstract

This report presents the results of LAP Benchmark v2, a controlled evaluation measuring how API documentation compression affects the task performance of AI coding agents. We test five documentation tiers - no documentation, original pretty-printed format, whitespace-minified, LAP-Standard (structured with descriptions), and LAP-Lean (types only) - across seven real-world production APIs spanning OpenAPI and AsyncAPI formats. Agents were evaluated on 70 tasks using a weighted scoring rubric (60% endpoint identification, 30% parameter accuracy, 10% code quality). Results show that LAP-format tiers achieve 70-95% token reduction in documentation size while maintaining task completion scores within 2-5 percentage points of the full-format baseline. The no-documentation baseline confirms that API documentation is critical for accurate endpoint identification. LAP-Lean achieves the best score-per-token efficiency, making it the recommended tier for production AI coding workflows where inference cost and context window utilization matter.

2 Methodology

5-Tier Documentation System

Each API specification is compiled into five documentation tiers that span the spectrum from no documentation to the most verbose original format:

TierDescriptionTypical SizeFormat Notes
none No documentation provided (prior-knowledge baseline) 0 tokens Agent must rely solely on training data
pretty Original format with full whitespace and comments Baseline (1x) YAML/JSON/GraphQL as-downloaded from source
minified Whitespace removed, comments stripped ~30-70% of pretty Machine-readable, hard for humans to read
lap-standard LAP structured format with endpoint descriptions and parameter types ~10-40% of pretty Structured text block, human and AI readable
lap-lean LAP format with types only - no descriptions, no examples ~5-20% of pretty Maximum compression while preserving endpoint schema

Scoring Rubric

Each run is scored on a 0-1 scale using three weighted components:

ComponentWeightWhat it Measures
Endpoint Identification (EP)60%Correct API endpoint path and method identified and used
Parameter Accuracy (Par)30%Required and optional parameters present with correct types
Code Quality (Code)10%Executable Python code in response with endpoints and params in code blocks

Total score = 0.6 * endpoint + 0.3 * params + 0.1 * code

Confounding Variable Mitigations

The benchmark applies several controls to isolate documentation quality as the independent variable:

  • Neutral filenames: All documentation tiers are delivered as api_docs.txt to prevent tier/format leakage into the agent context
  • Business-language tasks: All 100 task descriptions (14 used in pilot) are phrased in domain language without endpoint-revealing technical terms
  • No-doc baseline (none tier): Establishes agent prior knowledge without documentation
  • Python-only mandate: Prompt enforces Python code output, eliminating language choice as a variable
  • No library hints: Prompt specifies "appropriate libraries" without naming specific SDKs
  • Agent isolation: Each run uses double-UUID nested temp directories to prevent cross-run contamination
  • Error handling: The one error run (digitalocean minified t2) is excluded from averages but included in the appendix

11 Discussion

LAP-Lean: Best Efficiency Tier

LAP-Lean achieves an average score of 0.917 - within 0.030 points of the pretty baseline (0.888) - while delivering approximately 90% documentation token reduction. This translates to roughly 28% inference cost savings per run. For production AI coding workflows where agents are invoked at scale, LAP-Lean offers the best score-per-token efficiency.

No-Doc Baseline: Documentation Is Essential

The no-documentation baseline scores 0.427 on average - substantially below all documented tiers. The primary failure mode is endpoint identification (EP score): without documentation, agents cannot reliably identify the correct API endpoint path for unfamiliar or domain-specific APIs. This confirms that documentation is not merely helpful but essential for reliable AI agent performance, particularly for endpoints that are not prominent in the agent's training data.

Minification Provides Little Benefit Over Pretty

The minified tier (whitespace removed) achieves 0.886 vs 0.888 for pretty. Despite removing whitespace, minification of YAML/JSON does not meaningfully reduce semantic token count because the structural keywords, field names, and values remain unchanged. In some cases (notably Stripe, which has a multi-megabyte OpenAPI spec), minification can actually increase effective context usage by triggering more context window pressure without improving information density. LAP-format representations are fundamentally different: they reorganize information into a denser, agent-optimized structure rather than simply removing whitespace.

LAP-Standard: Intermediate Trade-off

LAP-Standard includes full descriptions alongside the structured schema, achieving approximately 85% documentation savings vs pretty. It scores consistently well and may be preferable for agents working with unfamiliar APIs where natural language descriptions of endpoints provide additional disambiguation context. The difference between LAP-Standard and LAP-Lean in this pilot is minimal, suggesting that for the tested task types, type information alone is sufficient for correct task completion.

12 Conclusion

This pilot benchmark demonstrates that LAP format compression achieves approximately 90-95% token reduction in API documentation size while maintaining agent task performance scores within 5 percentage points of the full-format baseline. The LAP-Lean tier achieves an average score of 0.917 with roughly 28% cost savings per inference run - making it the recommended format for production AI coding workflows.

Documentation is a critical prerequisite for AI agent accuracy: the no-documentation baseline confirms that agents cannot reliably identify API endpoints from training knowledge alone, particularly for domain-specific or less-prominent APIs. Simple whitespace minification provides negligible benefit; structured compression (LAP format) is required to achieve meaningful token reduction without quality loss.

Recommended Production Configuration

  • Use LAP-Lean for high-volume, cost-sensitive AI coding agent deployments
  • Use LAP-Standard when working with complex or ambiguous APIs where descriptions improve disambiguation
  • Avoid minified format - provides no meaningful benefit over pretty and increases cognitive load for the agent
  • Always provide some documentation - the no-doc baseline demonstrates significant quality degradation

Future Work

  • Full benchmark run: 500 runs across 50 specs (OpenAPI, AsyncAPI, GraphQL, Protobuf, Postman)
  • Multiple models: Compare results across GPT-4o, Gemini Pro, and local LLMs
  • Repetition trials: n >= 3 per condition for statistical significance
  • Randomized tier order: Eliminate potential ordering bias
  • Complex task types: Multi-step workflows, error handling, pagination
  • Streaming/async APIs: Expand AsyncAPI coverage and task variety
